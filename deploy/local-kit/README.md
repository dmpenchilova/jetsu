# jet.su — сайт и админка на своём компьютере

Сборка для тестирования: сайт «Инфосистемы Джет» и его админка (Payload CMS). Всё работает у вас на ноутбуке в Docker и никуда не отправляет данные: письма о заявках попадают в тестовый ящик.

Версии в архиве: админка `7884807`, сайт `dbb4183` (от 27.09.2026).

## Что внутри

| Папка / файл | Что это |
|---|---|
| `jetsu-main/` | админка и API сайта (Payload CMS 3, PostgreSQL) |
| `jet-front-main/` | сайт (Next.js) |
| `start.sh` / `start.ps1` | запуск одной командой (macOS / Windows) |
| `stop.sh` / `stop.ps1` | остановка |
| `export.sh` / `export.ps1` | выгрузить содержимое своей копии в файл для коллег |
| `import.sh` / `import.ps1` | загрузить содержимое, полученное от коллеги |

Папки должны лежать рядом, как в архиве. Переименовывать их нельзя.

## 1. Подготовка (один раз)

1. Установите **Docker Desktop**: https://www.docker.com/products/docker-desktop/ и запустите его.
2. В Docker Desktop → Settings → Resources дайте не меньше **6 ГБ памяти** (лучше 8). Иначе сборка админки может упасть.
3. Нужен интернет: при первой сборке скачивается около 2 ГБ.
4. Порты **3000, 3001, 5432, 8025** должны быть свободны. Если у вас уже запущен свой PostgreSQL, остановите его.

## 2. Запуск

Распакуйте архив, например в «Загрузки».

**macOS / Linux.** Откройте Терминал и выполните:

```bash
cd ~/Downloads/jetsu-local
bash start.sh
```

**Windows.** Откройте папку `jetsu-local`, щёлкните правой кнопкой по `start.ps1` и выберите «Выполнить с помощью PowerShell». Если Windows не даёт запустить, откройте PowerShell в этой папке и выполните:

```powershell
powershell -ExecutionPolicy Bypass -File start.ps1
```

Первый запуск занимает 15–25 минут: скачиваются и собираются админка и сайт, загружаются тестовые данные. Следующие запуски — 1–2 минуты.

Когда в окне появится «Готово», откройте:

- **админка:** http://localhost:3001/admin
- **сайт:** http://localhost:3000
- **тестовая почта:** http://localhost:8025 (письма о заявках с сайта)

## 3. Первый вход в админку

При первом открытии админка предложит создать пользователя. **Первый созданный пользователь становится администратором.** Пароль администратора — не короче 14 символов: заглавные и строчные буквы, цифры и спецсимвол.

Остальных коллег администратор заводит сам: «Пользователи» → «Создать», роли: администратор, редактор, автор, HR.

## 4. Что можно проверить

- **Страницы и конструктор.** «Страницы» → откройте любую. Справа превью: клик по блоку в превью открывает его поля. Попробуйте «Добавить блок», скрыть блок, поменять порядок, «Оформление и показ» (фон, отступы, расписание показа).
- **Публикация.** Изменения сохраняются черновиком автоматически. На сайт попадают после «Опубликовать». «Ссылка для коллег» показывает черновик без входа.
- **Шаблоны и общие блоки,** копирование страниц, «Проверка страницы» перед публикацией.
- **Поиск по админке:** ⌘K (Mac) или Ctrl+K (Windows).
- **Главная админки:** блок «Требует внимания».
- **Разделы:** публикации, проекты, мероприятия, услуги, вакансии, партнёры, сотрудники, клиенты, награды, опросы, уязвимости (на сайте — http://localhost:3000/vuln/).
- **Формы и заявки.** Отправьте форму на сайте (например, на http://localhost:3000/contacts/), письмо придёт на http://localhost:8025, заявка — в «Заявки».
- **Английская версия:** переключатель «Локаль» вверху админки, сайт — http://localhost:3000/en/
- **Настройки сайта:** хедер, футер, 404, редиректы, переменные {{…}}, SEO, режим обслуживания (после включения сайт через 30 секунд показывает «Ведутся работы»).
- **Безопасность:** «Мой профиль» → «Двухфакторный вход».
- **Справка по работе:** в меню «Справка» (http://localhost:3001/admin/help).

Все изменения видны только на вашем компьютере.

## 5. Работа в команде: у каждого своя копия

Архив можно раздать сколько угодно коллегам. Каждый запускает его у себя, и копии друг от друга не зависят: правки одного не видны другим, никто никому не мешает.

Когда нужно показать свои наработки (собранные страницы, настройки, загруженные картинки):

1. Тот, кто делал, **выгружает** содержимое:
   - macOS: `bash export.sh`
   - Windows: `export.ps1` (правой кнопкой → «Выполнить с помощью PowerShell»)

   Рядом со скриптами появится файл `jetsu-content-<дата>.tar.gz`. Его можно переслать в мессенджере или по почте.
2. Коллега кладёт файл в свою папку `jetsu-local` и **загружает** его:
   - macOS: `bash import.sh` (или `bash import.sh путь/к/файлу.tar.gz`)
   - Windows: `import.ps1`

Важно:
- Загрузка **заменяет всё** содержимое копии, включая пользователей. После загрузки входите под учётной записью того, кто выгрузил файл. Хотите сохранить своё — сначала выгрузите его.
- Файлы из заявок (резюме и т. п.) не передаются, только сами записи заявок.
- Выгрузка и загрузка работают между копиями из **одного и того же архива**. Если архив обновился, сначала обновите копию.

## 6. Остановка, повторный запуск, сброс

| Действие | macOS / Linux | Windows |
|---|---|---|
| Остановить | `bash stop.sh` | `stop.ps1` |
| Запустить снова | `bash start.sh` | `start.ps1` |

Начать с чистого листа (удаляет **все** данные, пользователей и файлы этой локальной копии):

```bash
cd jetsu-main
docker compose down -v
rm -f .fixtures-imported          # Windows: del .fixtures-imported
```

Затем снова `start.sh` / `start.ps1`.

## 7. Если что-то не работает

- **«Docker Desktop не запущен»** — запустите Docker Desktop и дождитесь, пока он загрузится.
- **Сборка админки падает с ошибкой памяти** (`Killed`, `exit code 137`) — увеличьте память в Docker Desktop (раздел 1) и запустите снова.
- **«port is already allocated»** — порт занят другой программой. Закройте её (часто это локальный PostgreSQL на 5432) и запустите снова.
- **Сайт долго не открывается** при первом запуске — это нормально, он собирается 5–10 минут. Ход сборки: `cd jetsu-main && docker compose logs -f front` (выход — Ctrl+C).
- **Журнал админки:** `cd jetsu-main && docker compose logs admin --tail 50`

Если не помогло, пришлите снимок экрана с ошибкой.
