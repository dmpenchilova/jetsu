# Запуск на боевом сервере

Всё работает на одном сервере в Docker: сайт, админка, база данных, HTTPS-сертификаты и ночные резервные копии.

## Что нужно заранее

1. **Сервер (VPS)** в России: Ubuntu 22.04 или 24.04, от 4 ГБ памяти, 2 ядра, 40 ГБ диска.
2. **Два домена**, которые указывают на IP сервера (DNS-записи типа A):
   - сайт, например `jet.su` (и `www.jet.su`);
   - админка, например `admin.jet.su`.
3. **Почтовый ящик для отправки писем** (SMTP): адрес сервера, порт, логин, пароль.
4. **Ключи Яндекс SmartCaptcha** (клиентский и серверный). Без них капча выключена.
5. **Список сетей компании** (IP-адреса), из которых можно входить в админку. Если его не задать, вход будет открыт отовсюду (с паролем).

## Установка

Команды выполняются на сервере под пользователем с правами администратора.

```bash
# 1. Docker
curl -fsSL https://get.docker.com | sh

# 2. Код: админка и сайт — в соседних папках
mkdir -p /srv && cd /srv
git clone https://github.com/<организация>/jetsu.git
git clone https://github.com/<организация>/jet-front-main.git

# 3. Настройки
cd /srv/jetsu/deploy
cp .env.example .env
nano .env        # заполните домены, секреты, почту, капчу

# 4. Запуск (первая сборка — 10–15 минут)
docker compose -f docker-compose.prod.yml --env-file .env up -d --build
```

После запуска:

- сайт — `https://<SITE_DOMAIN>`;
- админка — `https://<ADMIN_DOMAIN>/admin`. Первый зарегистрированный пользователь становится администратором, поэтому зайдите туда сразу.

Секреты генерируются командой `openssl rand -hex 32`, для каждого нужен свой.

## Обновление

```bash
cd /srv/jetsu && git pull
cd /srv/jet-front-main && git pull
cd /srv/jetsu/deploy
docker compose -f docker-compose.prod.yml --env-file .env up -d --build
```

Изменения базы данных (миграции) применяются сами при запуске админки.

## Резервные копии

- Каждую ночь в 3:00 по Москве в папку `deploy/backups` записываются:
  - `db_<дата>.dump` — база;
  - `files_<дата>.tar.gz` — медиатека и файлы из заявок.
- Копии старше 14 дней удаляются (срок задаётся в `BACKUP_KEEP_DAYS`).
- Папку `backups` стоит регулярно копировать на другой сервер или в облачное хранилище.

### Восстановление

```bash
cd /srv/jetsu/deploy
docker compose -f docker-compose.prod.yml stop admin front

# база
docker compose -f docker-compose.prod.yml exec -T db \
  pg_restore --clean --if-exists --no-owner -U jet -d jet_admin < backups/db_<дата>.dump

# файлы
docker compose -f docker-compose.prod.yml run --rm -v "$PWD/backups:/backups" backup \
  sh -c 'cd /data && tar -xzf /backups/files_<дата>.tar.gz'

docker compose -f docker-compose.prod.yml start admin front
```

Для восстановления файлов тома медиатеки в сервисе `backup` подключены только для чтения. На время восстановления уберите `:ro` у строк `media` и `private_uploads` в `docker-compose.prod.yml`.

## Безопасность

- **HTTPS.** Сертификаты Let's Encrypt Caddy получает и продлевает сам.
- **Заголовки.** Включены HSTS, `nosniff` и строгий Referrer-Policy. Сайт можно встроить во фрейм только в админке (для живого превью).
- **Доступ к админке.** Вход и служебный API открыты только из сетей `ADMIN_ALLOW_IPS`. Файлы медиатеки, API сайта и приём заявок доступны всем, иначе сайт не будет работать.
- **База.** Наружу не открыта.
- **Файлы из заявок** (резюме и т. п.) хранятся отдельно от медиатеки и выдаются только после входа в админку.
- **Пароли.** Для редакторов — не короче 12 символов, для администраторов — не короче 14. После 5 неудачных попыток входа учётная запись блокируется на 15 минут.
- **Журнал.** Все действия пользователей записываются в «Журнал действий».

## Тестовый стенд

Для тестового стенда используйте отдельный сервер или другие домены с таким же `.env`. Затем в админке откройте «Настройки сайта → SEO и индексация» и снимите галочку «Разрешить поисковикам индексировать сайт».
